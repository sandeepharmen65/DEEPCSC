# Deep CSC customer website preview

Open `index.html` in a browser to view the responsive customer website. This folder is the public-facing design preview only. To run the Razorpay backend bridge with the website, follow `../deep-csc-payment-backend/README.md`; opening the HTML file directly keeps payments in preview mode.

The visual update draws on all 26 supplied clips: dashboard cards and charts, OTP entry, search expansion, upload confirmation, favorite state, share and delete controls, animated navigation, send/publish/payment states, receipt and checkout styling, and responsive dashboard layouts. Sign-in/sign-up use the cream-and-emerald split panel; customer OTP verification uses the dark glass, glow and four-box style from the supplied OTP clip.

The site copy is tailored to Deep CSC in Chhajli, Sunam: the 24-hour service, WhatsApp contact, customer-help options, Punjab service directory, free home visits within 10 km and ₹20 per additional kilometre. English, Punjabi and Hindi are available for the main page and home-visit booking flow. Search the service names or filter A–Z; selecting a service reveals its own starter checklist and named upload columns. Select JPG/PDF files to reveal the related handwritten fee estimate. Clear written totals stay labelled as listed, while unclear/range-based rows remain estimates until Deep CSC confirms the current portal charge.

Job and recruitment forms also show a job/post notice upload and a description field with a live word counter. The customer must enter at least 150 words before review; that description and the selected JPG/PDF files are included in the WhatsApp share request.

Files are limited in this preview to JPG/PDF under 10 MB and stay on the device until the customer chooses WhatsApp in the native share sheet. The share flow checks support for each data field, shares the actual files array, and treats a user cancellation as cancelled instead of claiming the files were sent. If sharing is unavailable, the page asks the customer to attach the files manually in WhatsApp; the message does not include file names.

The live owner dashboard is served by `../deep-csc-payment-backend` at `/admin` after its private owner account is configured. It is not a static public page.

## Before a real launch

This remains a preview until hosted behind HTTPS. Customer account registration/sign-in now calls the backend: passwords are scrypt-hashed, sessions use random HttpOnly/SameSite cookies, sign-in is rate-limited, and application records are scoped to the signed-in account on every query. Customers can enable an authenticator app (six-digit TOTP) as a second sign-in step. Authenticator secrets are encrypted at rest when the server encryption key and `cryptography` package are configured. The four-digit customer phone-code screen is still a visual preview; sending/verifying that code requires an SMS/WhatsApp OTP provider. Customer phone numbers are not verified during registration yet. Do not collect documents or treat customer identity as verified until that provider and private upload storage are connected. The browser's native share window only hands files to an app the customer chooses; it is not protected server storage. Payments remain disabled until the Razorpay server is configured with merchant keys, webhook secret, HTTPS hosting, and an owner-approved quote.

The uploaded UPI QR is kept in the backend's ignored private-data folder and is not displayed in this preview or the older static portal. Static websites cannot keep QR or UPI details private once deployed. Deploy only this `deep-csc-final` folder. For launch, use the approved hosted gateway flow after owner approval and a server-confirmed amount; do not expose merchant secrets in browser code.

Document checklists and listed prices are starter guidance copied from the customer's notes. Confirm current Punjab portal requirements, government charges, cafe fees, and totals before publishing final prices. Home-service charges are shown as requested.

## Customer policies and consent

`legal.html` contains the privacy policy, terms, cookie policy, refund/cancellation policy, third-party disclosures, review/claims and copyright guidance, business contact details, and official India/Punjab law references. The home-visit form, application form, account registration, tracking/help request forms, and payment checkout require the applicable customer consent action before sharing or paying. A cookie-choice banner controls the optional Google Fonts request; rejecting it keeps system fonts. WhatsApp, Razorpay and government sites are named as separate providers, and the page does not include fabricated reviews or unsupported government-affiliation claims.

The policy text is a practical draft and preview disclosure, not legal advice. The proprietor's legal name, verified business email, and any legally required grievance-officer identity/designation have not been provided. Confirm these details and the business's applicable Punjab registrations before a public commercial launch. The private owner dashboard is implemented in the backend, but an owner account must still be created on the proprietor’s laptop with `python setup_admin.py`; the default access list allows only local connections. Customer request metadata is recorded after the displayed consent and share action when the website and backend run together. Actual document contents remain on the customer device until shared through the selected app. No public admin access or document upload/storage service is configured. Customer phone OTP delivery and production hosting/database must be configured before launch.

## Security checks

The preview checks JPG/PDF filename, file signature and a 10 MB maximum before opening the device share flow; this is browser-side validation only. The backend uses parameterized queries, account-bound application queries, password hashing, expiring sessions, CSRF/origin checks, persistent rate-limit events, and a restrictive Content Security Policy. SQLite local mode uses server-side ownership filters. Managed PostgreSQL mode uses the included migration to enable and force RLS on customer application rows, with the verified session ID set for each application transaction. No customer-upload endpoint or customer-supplied URL fetch exists. The `_headers` file supplies CSP and related response headers on Cloudflare Pages and Netlify; switch on HTTPS redirects at the chosen host. Live payment and account traffic must be deployed behind a trusted HTTPS proxy and reviewed before launch.
